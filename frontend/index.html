      What you are looking at

      1. Ingest — an EDI 214 is the carrier’s status fax, in machine form. Cloud analog: S3 inbound bucket + event.
      2. Parse — we pull PRO, parties, promised date, and AT7 events. Cloud analog: Lambda / worker.
      3. Store — one shipment row, many events. Cloud analog: RDS.
      4. API — the dashboard is just another client of /api/shipments.
      5. Alerts — missed promise or carrier delay code A9. Cloud analog: EventBridge + SNS/SES.

      Walk these in order with the README lesson plan. Then open docs/ARCHITECTURE.md for scale, security, availability, and cost.
